## 宿題

- **取り組んだレベル：** 基礎

- **やったこと：**
  `app/agent.py`の`INSTRUCTIONS`を変更し、AIエージェントのツール利用に関する指示が、回答内容やツールの呼び出し回数に与える影響を検証した。
  具体的には、用語集を「必ず検索する」という指示を、「必要に応じて検索する」という指示に変更した。
  変更前後で同じGemini 3.5 Flash Liteモデルを使用し、「LoRAとQLoRAの違いは？」という同一の質問を`--trace`付きで実行した。

  使用したコマンド：
  `uv run python -m app.agent --trace "LoRAとQLoRAの違いは？"`

  実行結果をそれぞれ`/tmp/lec03_before.txt`と`/tmp/lec03_after.txt`に保存し、ツールの呼び出し回数、引数、LLMの呼び出し回数、トークン数、回答内容を比較した。

- **結果（`--trace`の出力や比較）：**

  | 評価項目 | 変更前 | 変更後 |
  |---|---|---|
  | 使用モデル | Gemini 3.5 Flash Lite | Gemini 3.5 Flash Lite |
  | `search_glossary`呼び出し回数 | 2回 | 2回 |
  | ツールの引数 | LoRA、QLoRA | LoRA、QLoRA |
  | LLM呼び出し回数（requests） | 2回 | 2回 |
  | 入力トークン数 | 1,384 | 1,382 |
  | 出力トークン数 | 193 | 226 |
  | APIコスト（USD） | 0.0008977 | 0.0009796 |

  **変更前のツール呼び出し：**

  ```text
  [tool call] search_glossary({'query': 'LoRA'})
  [tool call] search_glossary({'query': 'QLoRA'})
  [usage] requests=2, tool_calls=2
  ```

  **変更後のツール呼び出し：**

  ```text
  [tool call] search_glossary({'query': 'LoRA'})
  [tool call] search_glossary({'query': 'QLoRA'})
  [usage] requests=2, tool_calls=2
  ```

  **回答内容の比較：**

  変更前は、LoRAについて、事前学習済みの重みを固定し、低ランク行列（アダプタ）だけを学習するPEFT手法と説明した。QLoRAについては、ベースモデルの重みを4ビットなどに量子化することでGPUメモリの使用量を削減する手法と説明した。
  変更後も同様の説明が得られたが、Low-Rank AdaptationやQuantized LoRAの正式名称、Quantizationの説明などが加わり、回答がやや詳細になった。
  どちらの条件でも`search_glossary`がLoRAとQLoRAに対して各1回呼び出され、用語集に基づいた回答が生成された。
  指示文を変更してもツールの呼び出し回数は変化しなかった。一方、出力トークン数は193から226に増加し、APIコストも約9.1%増加した。

- **気づき・疑問：**

  今回の実験から、ツールを使用する指示を緩和しても、必ずしもツールの使用回数が減るわけではないことがわかった。
  「LoRAとQLoRAの違いは？」という質問では、2つの専門用語を正確に比較するために、変更後もAIが用語集の検索を必要と判断した可能性がある。
  また、両条件とも検索回数とLLM呼び出し回数は同じだったが、回答の文章量やトークン数には違いが見られた。これは、LLMの出力が同じ質問でも一定ではないという性質と整合する。
  したがって、今回の1回ずつの比較だけでは、回答の変化が指示文の変更によって生じたのか、生成時のばらつきによるものなのかを明確に区別することはできない。
  今後は各条件で同じ質問を複数回実行し、検索回数や回答品質の平均的な変化を比較したい。また、講座固有の知識を尋ねる質問と、一般的な知識で回答できる質問を使い分けることで、INSTRUCTIONSの違いがツール選択に与える影響をより詳しく調べたい。
