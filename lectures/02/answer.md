## 演習

  - `lr`：0.0002

  - `warmup_steps`：6

  - `max_new_tokens`：96

- **自分で学習を実行したか（`executed_training_myself`）：** はい（`true`）。Qwen3.5-0.8Bを用いてLoRAによる追加学習を実施し、学習前後の21問について評価した。さらに宿題ではLoRAランクを変更して再学習した。
- **学習前：** `format_rate` = 0.0952（9.52%、2/21） / `content_rate` = 0.0000（0%、0/21）
- **学習後：** `format_rate` = 1.0000（100%、21/21） / `content_rate` = 0.8571（85.71%、18/21）

- **退行した質問：**
  `result.json`の`regressed`は空配列であり、退行した質問は記録されていなかった。LoRAランクを8に変更した場合も同様に退行は記録されなかった。

- **学習後に残った失敗と、その型（根拠なしの質問に断定した / 根拠ありの質問に確認要求で逃げた / 形式の崩れ）：**
  学習後の`format_rate`は100%となり、評価した21問ではJSON形式の崩れは発生しなかった。
  一方、`content_rate`は85.71%であり、21問中3問で内容判定が不正解となった。個々の不正解の詳細は、今回の`result.json`だけでは特定できない。
  知識を問う追加質問では、「この講座の最終課題の締切はいつですか」というFAQに根拠のない質問に対して、「課題の提出期限は9月30日23:59（日本時間）です」と回答し、`needs_review: false`として断定した。これは、別の課題の提出期限を最終課題の締切に当てはめた誤答である。
  したがって、LoRAによってJSON形式の遵守率は改善したものの、根拠のない情報について適切に確認を求める判断には課題が残った。

- **知識を問う質問（セクション6）の結果（学習前の分類 → 学習後の分類）と気づいたこと：**
  | 質問 | 学習前 | 学習後 |

  | この講座の最終課題の締切はいつですか | format_error | asserted |

  | 次回の講義のテーマは何ですか | format_error | needs_review |
  | 課題の提出期限はいつですか | format_error | asserted |

  いずれのLoRAランクでも分類結果は同じであった。
  学習前は4問すべてで指定されたJSON形式を守れなかったが、学習後は形式が整った。また、担当教員名や次回講義テーマについては、FAQに記載がないことを認識し、確認が必要だと回答した。
  一方、最終課題の締切については、FAQにある別の提出期限を流用して断定しており、形式が正しいことと内容が正しいことは別の問題であると理解した。
  なお、JSON上では「課題の提出期限はいつですか」も`FAQ にある: false`と記録されているが、演習資料ではFAQに根拠がある対照質問として扱われているため、この項目のフラグと評価設定については確認が必要である。- **学習で変わったこと・変わらなかったこと：**
  LoRAによる追加学習の結果、形式遵守率が9.52%から100%に、内容正解率が0%から85.71%に改善した。特に、`answer`と`needs_review`を含むJSON形式を安定して出力できるようになったことから、LoRAは回答形式や振る舞いの学習に有効だと考えられる。
  一方、FAQに記載のない質問への回答では、確認を求める場合と、根拠のない情報を断定する場合が残った。したがって、Fine-Tuningによって出力形式を改善できても、根拠に基づく判断の正確性まで保証されるわけではないことを確認した。

## 宿題
- **取り組んだレベル：** 基礎

- **変えた設定やデータ：**
  標準設定のLoRAランク`lora_r=16`を`lora_r=8`に変更し、同じモデル、同じ学習データを使用して再学習した。
  そのほかの設定である学習率`lr=0.0002`、エポック数20、`lora_alpha=32`、`seed=42`などは変更しなかった。
  LoRAランクを半分にすることで、学習する追加パラメータ数を減らした場合に、形式遵守率や内容正解率がどのように変化するかを検証した。

- **結果（比較表や数字）：**

  | 評価項目 | r=16（標準） | r=8（変更後） |
  |---|---:|---:|
  | 学習前 format_rate | 9.52% | 9.52% |
  | 学習前 content_rate | 0.00% | 0.00% |
  | 学習後 format_rate | 100.00% | 100.00% |
  | 学習後 content_rate | 85.71% | 90.48% |
  | 学習後 both_rate | 85.71% | 90.48% |
  | 学習前の評価所要時間 | 48.6秒 | 38.5秒 |
  | 学習後の評価所要時間 | 41.9秒 | 45.2秒 |
  | 最終Training Loss | 要追記 | 要追記 |
  | 学習時間 | 要追記 | 要追記 |
  | 退行した質問 | なし | なし |

  LoRAランクを16から8に変更した結果、学習後の形式遵守率はどちらも100%であった。一方、内容正解率は85.71%から90.48%へ4.76ポイント改善した。これは、21問の評価において正解数が18問から19問に増加したことを意味する。
  また、学習後の21問の評価にかかった時間は、r=16で41.9秒、r=8で45.2秒であった。ただし、これらは評価時の応答生成時間であり、LoRA自体の学習時間ではない。
  今回の実験では、LoRAランクを小さくしても形式遵守率を維持でき、内容正解率も低下しなかった。ただし、2条件について各1回の学習結果であるため、r=8が常にr=16より高精度になるとは結論できない。乱数やGPU上の計算のばらつきも考慮し、複数回の検証が必要である。

- **ファインチューニングが向く場面・向かない場面についての考察：**
  Fine-Tuningは、回答のJSON形式、文章の書き方、出力手順など、モデルの振る舞いを安定させたい場合に適していると考えられる。今回の実験でも、LoRAによる追加学習によって形式遵守率が9.52%から100%に改善し、その有効性を確認できた。
  また、LoRAは元のモデルの重みを固定し、少数の追加パラメータだけを学習するため、Full Fine-Tuningと比べて学習に必要なメモリを削減できる。今回の実験では、ランクを16から8に減らしても評価精度を維持できたことから、パラメータ効率を考慮した設定の最適化が重要だと感じた。
  一方、正確な最新情報や頻繁に更新される知識を扱う場合、Fine-Tuningだけでは十分ではない。実際に、今回の学習後のモデルは、FAQにない最終課題の締切を既存の提出期限と取り違えて断定した。

  したがって、回答形式や手順の統一にはFine-Tuningを活用し、正確な根拠が必要な情報についてはRAGなどの外部資料を参照する仕組みと組み合わせることが有効だと考えられる。
  今後は、LoRAランクをさらに変更して学習時間、最終Loss、正解率を比較し、少ない計算資源で必要な性能を確保できる条件を検討したい。
